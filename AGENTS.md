## Architecture/invariants

- Node 22, CommonJS, Sequelize 6.37.3, SQLite. No new dependencies added. Use existing `npm test` built-in Node runner, not the old nonexistent Jest test directory.
- `config/runtime.js` is the runtime environment/path authority. Default development; explicit production; test `:memory:`. Do not use the bot's global connection/models in unit tests.
- `services/spooky/models.js` defines models on an injected connection without syncing/migrating. Four required migrations cover core, delivery, notifications and permanent badges (`20261001000000` through `20261001000003` in `migrations/`). BadgeOwnership is independent of seasonal deletion. Do not alter existing User/Holiday/SpookyStat tables silently.
- Mutations use `createEconomy(...).execute(...)` and its transaction. Every related write must receive `ctx.transaction`. Do not open nested economy transactions in a mutation callback.
- Construct the economy with explicit `configVersion: event.version` (now 4). Its historical default is 1; do not let live ledger entries silently use that default.
- One Discord interaction = one committed operation, potentially many ledger rows. A replay returns the stored receipt without rerolling. Deterministic worker keys are separate and event/guild scoped.
- Theft debits and credits equal amounts atomically. Negative/fractional resources are prohibited; candy capacity 80 applies to transfers too. A cap/permission/database failure must never be hidden as an Eye-find fallback.
- Discord calls happen **after commit**, outside transaction callbacks. Message delivery failure must not duplicate rewards. The queue covers use of the economy service; bypassing it forfeits its same-connection concurrency guarantees.
- Collection conversion now lives in services/spooky/collection.js. Every registered-player Eye credit must use creditEyes (including theft), resolving five-Eye conversion in the same root transaction. Raw economy helpers do not enforce this policy. Quarters/duplicates/eligibility updates must share that transaction.
- Only authorized admin repair may remove an erroneous only copy, with explicit last-copy intent and reason; it never revokes permanent badge ownership. Gameplay collection keeps allowPaused=false; trusted admin composition opts in and separately enforces ACTIVE/unarchived/registration.
- The first inventory copy cannot be consumed by duplicate conversion; exactly five extras yield a uniformly random missing piece. No missing piece means retain extras. Badges are permanent and never part of a seasonal delete cascade.
- `config.enabled=false` now disables the wired Spooky command and curse-message runtime. `getEventState` is a pure lookup, not a mutation guard. Rarity approval guard must be called by future acquisition logic.
