# Disabled commands and seasonal retirement

The human requested closing Winter `/throw` and `/slots`, removing the redundant `/badges` menu, and disabling all `/achievement` subcommands. These commands are excluded from startup loading and future registration in both environments. Cached requests are answered privately before looking up a handler, and direct command calls also return before reading members, options, balances or event state. Shop remains disabled under its prior policy. Badge/achievement ownership, inventory and wallets are retained; owned badges remain visible on `/profile`.

`config/disabled-commands.json` holds explicit messages for the paused names and legacy aliases. `services/disabled-commands.js` supplies the shared guard. The command-environment filter accepts both source command builders and offline definition entries, preventing paused commands from reappearing in registration plans. Individual modules have empty environment allowlists plus early return guards. Reopening any of these features requires deliberate removal of its pause policy and review of its original implementation.

Production previously had a simpler environment-only filter without seasonal checks or an event command retirement worker; its old Winter handlers remained live despite the development schedule being disabled. Production now receives the same availability helper, disabled Winter schedule and tested retirement worker, with minimal metadata added to its existing Spooky wrappers. Its own Spooky definitions/payment rules are preserved. Startup/minute cleanup retires paused commands and explicitly scheduled event commands after their event ends in the pinned guild, without deleting unrelated/server-only commands. Expired events are also rejected during execution. No Community, Sanity or profile-notification runtime is introduced.

Fresh Discord GETs inspected guild and global commands for both applications. Production had achievement/badges/throw/slots in its guild registry; development had achievement/badges. Both global registries were empty. Targeted deletes remove only paused entries and verify all other commands unchanged, including Profile, Fate, current Spooky and development Game. Global inspection/removal also protects against leftover old global menus.

Evidence and rollback copies are retained under ignored `.runtime/command-cleanup`. This change does not delete rewards/history, reset XP, change launch overflow dates, migrate schemas, rescore events, or send public messages. Concurrent Crown/check-in work in the checkout remains separate.

The startup retirement worker removed the paused guild commands before the targeted registry pass. Fresh GET verification found 9 production commands and 10 development commands, no paused names, and empty global registries; all other commands were preserved. Validation: 511 full-suite tests passed, followed by 7 final focused tests covering paused dispatch and lifecycle cleanup; offline registry audit and scoped whitespace checks passed. Actual deployed production modules also passed an isolated in-memory probe for direct/cached rejection, Profile availability, Spooky event-end boundaries and startup cleanup wiring.
